# ForPDA Next

Неофициальный iOS-клиент форума и сайта [4pda.to](https://4pda.to) — производная версия
[ForPDA](https://github.com/SubvertDev/ForPDA) (GPL v3 © 2022-2026 [Ilia Lubianoi](https://github.com/SubvertDev)
и контрибьюторы). Рабочее название; меняется в одном месте — `Project.swift` → `App.displayName`.

* Отдельный Bundle ID `com.qmurzik.forpdanext` — ставится рядом с оригинальным ForPDA.
* Минимальная версия iOS 17, основная цель — iOS 18 (iPhone XS и новее). API iOS 26 используются только под `#available`.
* Без аналитики и трекеров: PostHog и Sentry удалены, логи только локальные и без персональных данных.

## Что изменено относительно ForPDA

### Надёжность соединения (`Modules/Sources/APIClient/Connection`)
Найденные первопричины «страницы не грузятся / помогает только перезапуск»:

| Проблема в оригинале | Исправление |
|---|---|
| Ошибка `connect()` при возврате из фона глушилась (`try?`) и больше не повторялась → все запросы падали до перезапуска | `ConnectionSupervisor` повторяет подключение с экспоненциальной задержкой (1→30 с, джиттер), сбрасывается при смене сети/возврате в приложение и по кнопке «Повторить» |
| Независимые задачи connect/disconnect при смене scenePhase могли выполниться в обратном порядке и закрыть свежий сокет | Все команды выполняются последовательно в одном actor по детерминированной `ConnectionPolicy` (покрыта тестами) |
| Переключение Wi-Fi ↔ LTE оставляло «мёртвый» сокет в состоянии ready, каждый запрос висел до таймаута 15 с | `NWPathMonitor` + переподключение при смене интерфейса; таймаут на «готовом» сокете считается признаком мёртвого соединения (не чаще раза в 10 с) |
| Запросы без сети ждали таймаута | Офлайн определяется сразу, показываются кэшированные данные и баннер состояния |
| `Int(response…)!` и индексация массива ответа без проверки → падения на неожиданном ответе | Безопасный разбор с ошибкой вместо краша |
| `stateStream` (single-consumer AsyncStream) читался напрямую | Единственный потребитель — супервизор, дальше рассылка подписчикам |
| Разрыв при кратком уходе в фон убивал отправку поста | Отключение в фоне с отменяемой отсрочкой 8 с (background task) |

Повторяются только безопасные (читающие) запросы, не более 3 раз. 31 пишущая операция (посты, репутация,
голосования, избранное, QMS …) никогда не повторяется автоматически.

### Новый редактор сообщений (`Modules/Sources/ComposerFeature`)
* `UITextView` — единственный источник истины: текст не перезаписывается из SwiftUI, поэтому не прыгает курсор,
  работают отмена/повтор, диктовка и предиктивный ввод. (В оригинале при «потерянном» выделении нажатие на тег
  заменяло **весь текст** парой тегов.)
* Панель форматирования над клавиатурой: Ж/К/П/З, цвет, размер, ссылка, цитата, код, спойлер (с заголовком),
  списки, выравнивание, оффтоп, HIDE, sup/sub, CUR/MOD/EX. Выделенный фрагмент оборачивается, без выделения —
  вставляются парные теги с курсором внутри; повторное нажатие снимает тег.
* Подсветка BB-тегов, проверка незакрытых тегов перед отправкой, счётчик символов (опционально).
* «Редактор / Просмотр»: предпросмотр делает сервер 4PDA и показывается тем же рендером, что и посты.
* Компактный режим (половина экрана) и полноэкранный; кнопка отправки всегда видна.
* Цитаты: несколько подряд, с автором/датой/ссылкой на пост, курсор после цитаты; ответ `[SNAPBACK]`.
* Вложения: фото (HEIC → JPEG, уменьшение до 2560 px), файлы из «Файлов», картинки из буфера, прогресс,
  отмена, повтор, переименование до загрузки, удаление (вместе со ссылками в тексте), вставка в позицию курсора.
* Черновики: отдельные для каждой темы/редактирования/диалога QMS, автосохранение, атомарная запись,
  вложения хранятся рядом с черновиком и догружаются после перезапуска. Список черновиков — в Настройках.
* Отправка: защита от двойного нажатия, черновик удаляется только после подтверждения сервера. Если исход неизвестен
  (таймаут/обрыв), сообщение **не переотправляется** — сначала проверяется последняя страница темы (или диалога).
  Маркер «отправка в процессе» переживает аварийное закрытие.

### Прочее
* Пять вкладок: Главная, Форум, Избранное, Сообщения (QMS), Профиль.
* QMS: полноэкранный редактор с черновиками, BBCode и вложениями (сервер принимает `attaches`).
  Редактирование сообщений QMS сервер не поддерживает — не имитируется.
* Настройки «Чтение и редактор»: размер текста постов, межстрочный интервал, ширина текста, плотность списков,
  размер аватаров, параметры редактора, экспорт/импорт локальных настроек (без логина и токенов).
* Стратегия открытия темы «Где остановился» (локальная позиция чтения, иначе — первое непрочитанное).
* Чёрная тема — настоящий `#000000` (OLED).
* App Group больше не вызывает краш, если после переподписи контейнер недоступен.

## Структура
* `Core/` — Swift-пакет `ForumCore` без зависимостей от UIKit: форматирование BBCode, цитаты, валидатор,
  черновики, защита отправки и проверка публикации, политика соединения и повторов, пагинация, позиции чтения.
  Собирается и тестируется на macOS **и Linux**: `swift test --package-path Core`.
* `Modules/Sources/*` — модули приложения (Tuist + The Composable Architecture), большинство — из ForPDA.
* Сетевой протокол 4PDA реализован в бинарном фреймворке `PDAPI` (из ForPDA, закрытый исходный код).

## Сборка
Нужны macOS, Xcode 26+ и [Tuist](https://tuist.dev) (версия в `mise.toml`).
```sh
tuist install && tuist generate
```

### IPA через GitHub Actions
Workflow `.github/workflows/build-ipa.yml` (runner `macos-26`) на каждый push:
1. тесты `ForumCore`; 2. юнит-тесты приложения на симуляторе; 3. неподписанный архив →
`ForPDA-Next-unsigned.ipa` с проверкой структуры `Payload/*.app` → артефакт **ForPDA-Next-unsigned-ipa**.

Неподписанный IPA **нельзя** установить напрямую: его нужно подписать (Sideloadly, AltStore, своя подпись).
Для подписанного IPA добавьте секреты репозитория `IOS_P12_BASE64`, `IOS_P12_PASSWORD`, `IOS_PROFILE_BASE64`
(профиль должен покрывать `com.qmurzik.forpdanext` и `com.qmurzik.forpdanext.safariextension`, удобнее wildcard) —
появится артефакт **ForPDA-Next-signed-ipa**.

## Известные ограничения
* Push-уведомления: ключ APNs сервера привязан к оригинальному ForPDA, поэтому в этой сборке уведомления работают
  через фоновое обновление iOS (не мгновенно). Notification Service Extension удалён.
* Протокол (`PDAPI`) — закрытый бинарный модуль ForPDA; изменения сетевого уровня сделаны поверх него.
* Упоминания на форуме создаются ответом с `[SNAPBACK]`; отдельного серверного API упоминаний нет.
* Размер текста/интервал применяются к страницам, загруженным после изменения настройки.
* Тестовые сообщения в реальные темы не отправляются: все тесты используют моки.
